# Журнал решений

Выборы с рассмотренными вариантами. Новые внизу. Пересматривайте свободно.

## 2026-09-25

1. **Нативное SwiftUI-приложение, а не локальный веб** (артефакт рекомендовал FastAPI + React).
   Решил пользователь: как Tandem и Selects. Довод сверху: монитор падений должен жить, когда
   ничего не открыто, — это агент в строке меню, а не вкладка браузера.
2. **Не Postman.** Конструктора запросов и форм нет. Практика — ячейка кода с кнопкой
   «Выполнить» и отображением результата по его форме. По сути Jupyter, привязанный к
   источникам, кредам, версиям и MCP.
3. **Секреты хранятся без шифрования** в `~/.practices/secrets.json` (0600, исключён из Time
   Machine, вне git). Решил пользователь: свои ключи на своей машине, внешних менеджеров не
   хочется. Снимает Keychain, age и окна доступа Keychain при ad-hoc подписи после каждой
   пересборки. Интерфейс хранилища оставляем узким, чтобы шифрование можно было добавить.
4. **Значения секретов не отдаются агенту через MCP**, несмотря на отсутствие шифрования.
   Причина не в защите файла, а в том, чтобы ключи не оседали в логах переписки и контексте
   модели. Агент видит имена переменных. Можно пересмотреть.
5. **«Встроить в проект» = скопировать код**, а не импортировать пакет из Practices. Связь
   держится меткой `# practices: <source>/<practice>@v<N>` в скопированном коде; по ней doctor
   находит устаревшие копии и копии, изменённые в проекте. Без метки обратная синхронизация
   невозможна — неизвестно, куда копировали.
6. **Структура как у Tandem:** Swift-пакет ядра `PracticesCore` с CLI `practicesctl` +
   приложение `PracticesApp` через xcodegen. Swift 6. Ядро не знает про UI; CLI — первый
   потребитель и заодно способ проверки без интерфейса.
7. **Монитор ходит в Docker через CLI `docker`, а не в сокет напрямую.** CLI сам знает
   текущий контекст (Docker Desktop сейчас, OrbStack потом), `docker events` отдаёт поток
   JSON. Цена — процесс на опрос и зависимость от формата `--format`. Альтернатива —
   HTTP поверх unix-сокета: быстрее, но свой клиент и выбор сокета по контексту вручную.
   Вернуться, если опрос станет заметен.
8. **Падения ловим по событиям, а не опросом.** `docker events` с фильтром по контейнерам:
   `die` с ненулевым кодом, `oom`, `health_status: unhealthy`, три `die` одного контейнера за
   пять минут — «перезапускается по кругу». Опрос `docker ps` и `lsof` только пока открыт
   поповер (раз в 3 с) и раз в минуту в фоне для значка.
9. **`die` с кодом 0, 130 и 143 не считаем падением** — это штатная остановка (`stop`,
   Ctrl-C, SIGTERM). 137 считаем: `docker stop` доходит до SIGKILL только если контейнер не
   остановился сам, и это тоже стоит знать. Ручные действия из самого приложения помечаются и
   не порождают уведомлений.
10. **Проект процесса вне Docker — по его рабочей папке** (`lsof -d cwd`), обрезанной до
    уровня `~/Projects/<имя>`. Для контейнеров — лейбл `com.docker.compose.project`.
11. **Данные пользователя в `~/.practices/`**, а не в `~/Library/Application Support`: туда же
    ходят CLI и агенты, короткий путь удобнее в терминале.
12. **OrbStack ставит пользователь сам** (этап 0 в PLAN): установка перенесёт контейнеры и
    остановит Docker Desktop, это не то, что делается фоном. Условия OrbStack: бесплатен для
    некоммерческого использования; пользователь использует его лично, решение за ним.
13. **Порты compose-файлов берём из `docker compose config --format json`**, а не парсим YAML
    сами: так применяются `.env`, интерполяция, `extends` и `!override` ровно как при `up`.
    48 файлов разбираются за ~2 с, пересчёт раз в 5 минут и при открытии поповера, если
    последнему скану больше минуты.
14. **Файлы `prod` / `stage` не сканируем** — они для серверов, их порты на этой машине шум.
    Папки с точкой (`.claude/worktrees`) и `node_modules`, `.venv`, `build`, `dist` пропускаем.
15. **Overlay-файлы разбираем поверх соседнего основного**: если файл один не собирается
    («neither an image nor a build context»), пробуем его поверх dev-файла, затем обычного,
    затем любого соседа. Не подошёл ни к одному — показываем как устаревший.
16. **Конфликт = порт занят кем-то, кроме контейнера этого же сервиса.** Сервис, который сейчас
    работает на другом порту, помечается «запущен на 5175». Столкновения двух проектов между
    собой, пока ни один не запущен, — только в `conflicts --all`, в поповере не показываем.
17. **Подсказка OrbStack — `service.project.orb.local:<порт контейнера>`.** Для портов баз и
    брокеров (5432, 6379, 9092…) ссылка в браузер не предлагается, только адрес для копирования.
18. **Rescan при открытии поповера, а не по FSEvents**: compose-файлы меняются редко, наблюдатель
    за деревом `~/Projects` стоит дороже пользы.

## 2026-09-25 — по макету главного окна (https://claude.ai/artifact/AdX3x71ik844Di7duqsafv)

19. **Окружение выбирает проект, а не окно.** Проект объявляет `source@env` для каждого
    источника (Kafka: локальный PLAINTEXT-брокер или боевой SCRAM). В окне вместо
    переключателя prod/dev — контекст «Проект: …», практики запускаются с кредами окружений
    этого проекта. Решил пользователь.
20. **Связка — тоже код**: `run()`, которая вызывает другие практики через
    `use("source/practice")`. Раннер записывает каждый вызов как шаг (время, объём, вход и
    выход), UI показывает шаги и промежуточные результаты. Копирование переносит связку и все
    её практики, каждую со своей меткой. Альтернатива — визуальный конвейер с привязкой полей
    мышью; отвергнута: пользователь работает кодом.
21. **Предложение из проекта = правка + объяснение + доказательства.** Агент присылает код,
    «что и почему» и свой набор параметров; Practices сам прогоняет старую и новую версии на
    сохранённых наборах и наборе агента и сравнивает форму и строки результата.
22. **MCP принимает предложение сам, если выполнены правила**: форма результата та же, строки
    на сохранённых наборах совпадают, не медленнее больше чем на 5%, источник не помечен
    «запись разрешена». Иначе — ревью пользователя с причиной. Автопринятия видны в истории
    и откатываются одной кнопкой. Пороги — предложение, уточнить после первых недель.
23. **Документация живёт у источника**: `registry/sources/<id>/docs/` — файлы (md, pdf, html)
    и ссылки, с пометкой «официальная / собранная / сгенерированная». Рядом
    `fields.yaml` — словарь полей: путь (`extra.acc_motion`), тип, смысл, значения и откуда
    взято описание. Всё в git реестра.
24. **Схема результата снимается с каждого прогона** (пути полей и типы, без значений). По ней
    поиск находит практики и связки, где поле есть в итоге, даже если имени поля в их коде нет.
25. **Поиск идёт по смыслу, в порядке**: поле в словаре → практики/связки, где поле в основном
    результате → документация (полный текст) → код и заметки практик → код проектов в
    `~/Projects` как подсказка «стоит сделать практикой». Тот же поиск — MCP `search`.
    Агент дописывает смысл полей через `describe_field` с тем же ревью, что и правки практик.
26. **Импорт Connectors раскладывает ключи по префиксам** (`XK_PG_`, `ARM_PG_` → xkeeper-pg и т.д.);
    заметки и защитные правила взяты из его README и SOURCES.md, не придуманы. Документы
    ссылаются на файлы Connectors, а не копируются: SOURCES.md перегенерируется там.
27. **Цель — `address` (`host:port`) или `url`**, оба — шаблоны над ключами `${KEY}`. Хосты
    приходят из секретов, поэтому сообщения проверок называют цель по id, не по адресу.
28. **`run` делает `execvp`**: команда заменяет процесс practicesctl, сигналы (Ctrl-C) и код
    выхода — её собственные. Конфликт одного ключа с разными значениями из двух источников —
    ошибка, а не «последний победил».
29. **Doctor ищет секреты своим однопроходным поиском** (фильтр по 2- и 4-байтным префиксам,
    параллельно по файлам), а не `grep -F`: 3 с против 2.5–4.5 мин на ~/Projects. Файлы больше
    1 МБ и папки с данными/зависимостями пропускаются. Значения сравниваются в процессе и
    никуда не выводятся; неизвестные секреты сводятся по SHA-256.
30. **В приложении разрешён HTTP без TLS (ATS `NSAllowsArbitraryLoads`)**: проверки и практики
    ходят во внутренние сервисы по `http://` (ClickHouse :8123). Без этого — ошибка −1022.
31. **Версия практики = номер коммита её файла в реестре** (`git log --follow`). Запуск
    несохранённого кода пишет файл без коммита и записывается как «черновик», не как версия.
32. **Практики самодостаточны**: подключение к источнику повторено в каждой (а не общий модуль),
    чтобы копия в проект работала сама. Код подключений взят из Connectors, не написан заново.
33. **Async-практики вызываются через фоновый event loop**, поэтому `use()` всегда синхронный:
    связка пишется как обычный код, даже если шаги асинхронные (XKDB).
34. **Маскируются только значения секретных ключей** (≥ 6 символов). Имена баз и пользователей —
    обычный текст, который законно бывает в результатах (`hyper_imu`, `readonly`).
35. **В истории прогонов нет данных**: время, объём, схема, шаги, ошибка. Прогон запроса к
    проду в песочнице не оставляет его копию на диске; результат живёт только в окне.
36. **Числа JSON сначала читаются как Int64**: `device_hash` — 64-битный, через Double он терял
    младшие разряды (−4896437846419584425 превращался в −4.896437846419584e+18).
37. **MCP-сервер — тот же `practicesctl`, stdio**, JSON-RPC построчно. Отдельного демона нет:
    каждая сессия агента запускает свой процесс, данные — в `~/.practices`, как у окна и CLI.
    CLI ставится в `~/.practices/bin` рядом с пакетом ресурсов (файлы Python-среды), ссылка —
    в `~/.local/bin`.
38. **«Строки совпадают» = SHA-256 канонического JSON всего результата**, а не превью. Время
    сравнивается по лучшему из двух прогонов каждой версии, допуск 5 % или 50 мс: на быстрых
    запросах через туннель разброс десятки миллисекунд, 5 % от 150 мс — шум.
39. **Старая версия падает, новая работает** — на наборе агента это ожидаемо (правка чинит
    ошибку) и не мешает автопринятию; на сохранённом наборе — повод для ревью.
40. **`describe_field` заполняет пробел, но не перезаписывает** существующее описание:
    возвращает его агенту. Спорные правки описаний — через заметки (`add_note`).
41. **Копия «изменена»**, если текст файла не совпадает с версией из метки и не содержит её
    тело целиком (копия может быть вставлена в больший файл).
42. **Пустая история реестра — ноль версий, а не ошибка**: на свежей установке `git log` без
    коммитов падает, и первую практику нельзя было сохранить (нашёл тест).
43. **Окружение `dev` заводится из локальных `.env` без показа значений**: `secrets import` берёт
    значение по имени из чужого файла, константы — литералом, общие с другим окружением — по
    `env:<имя>`. Совпадение паролей проверяется внутри процесса, наружу — только «да/нет».
44. **Псевдонимы переменных живут в `practices.yaml` проекта**, а не в реестре: имя переменной —
    свойство проекта. `init` находит их по совпадению значений (≥ 6 символов, одно
    совпадение), а не по похожести имён.
45. **Поиск по коду проектов — одна находка на файл**, первая внутри функции: список мест, а не
    вхождений. Черновик практики из функции — стартовая точка: зависимости из проекта
    переносит человек или агент, автоматически они не вытягиваются.
46. **Копия приложения для отрисовки и проверок не ставит значок в строку меню**
    (`MenuBarExtra(isInserted:)`): пользователь видел два значка, пока она жила.
47. **Правки своих ошибок в практиках идут через предложения**, как у агента: исправление
    числа партиций в `kafka/topics` меняло результат и честно ушло на ревью.
48. **Реестр пишет env-файлы проектов** (пересмотр §3.1 артефакта «файл на диск не пишется»):
    пользователь заводит новый источник в Practices и оттуда заполняет нужный файл нужного
    проекта. `run` остаётся для тех, кто хочет без файла. Файл пишется точечно: известные ключи
    меняются в своих строках, новые — в блоке `# >>> practices … # <<< practices`, который
    пересобирается; права 600, если в файл попадают секреты. Файл, отслеживаемый git, секретов
    не получает (только с --force); несекретные ключи туда писать можно.
49. **Имена переменных — знание реестра, а не проекта**: `names.yaml` у источника (в git),
    собирается по совпадению значений в env-файлах `~/Projects` и по псевдонимам манифестов.
    Рабочие проекты не переименовываются; новые подключения видят существующие имена и
    предупреждение, если выбирают ещё одно.
50. **Значок в строке меню — то, что требует внимания сейчас**: падение гаснет само, когда
    контейнер снова работает и здоров 10 минут (или по «Скрыть»). Все падения пишутся в
    `~/.practices/incidents.jsonl`: история событий Docker (OrbStack) — короткий буфер, и после
    факта по ней не восстановить, что падало.
51. **Высота поповера считается по содержимому** (до 620 pt): `ScrollView` своей высоты не
    имеет, и в окне строки меню схлопывался в ноль — поповер был пуст, хотя на отрисовке вне
    экрана выглядел нормально.
