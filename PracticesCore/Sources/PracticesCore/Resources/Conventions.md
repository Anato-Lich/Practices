# Соглашения пространства

Как устроены репозитории этого пространства. Агент читает их (`get_conventions`) перед новым
проектом, сервисом или правкой окружения; отступать — только по просьбе владельца. Файл и
`templates/` рядом с ним — личные правила владельца: правьте под себя.

## Модули

- `backend/` — сервер (Python, `uv`), `frontend/` — клиент (`npm`). Один репозиторий — один
  продукт; общий код — отдельным пакетом, не копией.

## Compose

- По умолчанию два файла: прод — `docker-compose.yml`, разработка — `docker-compose.dev.yml`.
  Имена — выбор владельца; если в пространстве принято иначе, исправьте здесь.
- Миграции — одноразовый сервис `migrate`; приложение ждёт его:
  `depends_on: {migrate: {condition: service_completed_successfully}}`. Это не сервис каталога.

## Переменные окружения

- `.default.env` — в git: все имена переменных со значениями для разработки, без секретов.
- `.env` — вне git (`.gitignore`): значения этой машины, `practicesctl connect … --to .env`.

## Порты

- Сотня `PP` на проект: `PP000+` — backend и воркеры, `PP100+` — frontend, `PP200+` — инфраструктура
  (базы, брокеры; наружу по умолчанию не публикуется, доступ через `docker compose exec`), `PP600+` — отладчики.

## Задачи IDE

- `.vscode/tasks.json` — вне git, из шаблона `templates/vscode/tasks.json`: test, lint, fix,
  typecheck, «frontend: lint», «dev: up», «dev: down», «dev: logs», «prod: up», «check: всё».

## Локальные домены

- Веб-входы получают домен, хостовые порты публикуются только для отладчиков. Какие домены
  (OrbStack `*.orb.local` / свои метки `dev.orbstack.domains`, или общий Traefik с зоной владельца) —
  решение владельца; запишите его здесь.
