# Задание дизайну: «Начало» и «Настройка» (2026-11-07)

Контекст: приложение будет жить на git и ставиться другим людям; всё личное (пути к клонам,
секреты, окружение Python, регистрация MCP, инструкции агентам) — на машине пользователя,
не в git и не в сборке. Настраивается при первом запуске вручную или агентом в диалоге
(те же шаги есть командами `practicesctl setup …`). Решение 36 в `DECISIONS.md`, шаг 7 в `PLAN.md`.

База — существующие `design/*.dc.html`, `tokens.md` (включая таблицу «Дополнения»), `NOTES.md`.
Новых цветов не вводить. Оба экрана — внутри того же окна 1280×860 с боковой панелью;
«Начало» — когда панель пуста (нет ни одного пространства), «Настройка» — обычный экран,
открывается из подвала боковой панели (значок шестерёнки рядом со счётчиками) и из палитры ⌘K.

## 1. «Начало» (первый запуск) — `Welcome.dc.html`

Состояние окна: боковая панель без пространств (только поиск, «Ждут приёмки 0», «Не
распределено», «Карта» — неактивные), в основной области — три шага сверху вниз, каждый со
статусом справа (не сделано / выполняется / готово / ошибка) и одной кнопкой действия.

1. **Где лежат клоны.** Список папок (`~/.practices/local.yaml → roots`), по умолчанию пусто;
   кнопки «Добавить папку…» (системный выбор папки) и «✕» у каждой строки. Под списком — что
   нашлось: «в 2 папках 34 клона, 21 с compose». Подсказка: «Не весь диск: только папки, где
   лежат проекты».
2. **Откуда взять каталог.** Два варианта в одном блоке: поле «URL репозитория пространства»
   + «Склонировать» (можно несколько раз — список склонированных с именем и числом проектов),
   или «Создать новое пространство» (имя + id). Состояния: клонируется (прогресс), склонировано
   (имя, N проектов, M сервисов), ошибка (нет доступа — текст моноширинным).
3. **Агенты.** Одна кнопка «Настроить агентов» с развёрнутым списком того, что будет сделано,
   с чекбоксами по умолчанию включёнными: «MCP-сервер в Claude Code (`~/.claude.json`)»,
   «блок инструкций в `~/.claude/CLAUDE.md`», «блок инструкций в `~/.codex/AGENTS.md`»
   (показывать только те инструменты, что найдены на машине: Claude Code / Codex / Cursor).
   После выполнения — строка состояния по каждому: «записан · 7 ноя», «обновлён», «не найден».

Внизу: «Открыть каталог» (активна, когда есть хотя бы одно пространство) и ссылка
«Настроить позже». Отдельный фрагмент: тот же экран, когда настройку ведёт агент —
статусы меняются сами, в шапке подпись «настраивает агент через MCP».

## 2. «Настройка» — `Settings.dc.html`

Тот же тулбар с хлебной крошкой «Настройка», справа «Проверить» (перечитывает всё).
Четыре секции карточками (SectionCard), в стиле страницы пространства:

- **Клоны.** Список корней с числом найденных клонов и датой последнего скана; «Добавить
  папку…», «✕»; отдельно «Папки без git» (из `local.yaml → folders`: имя → путь).
- **Пространства.** Таблица: id · название · remote (моноширинным, или «нет remote» с кнопкой
  «Задать…») · состояние git: ветка, незакоммиченное, ↑↓ отставание от remote · кнопки «Push»,
  «Pull». Внизу «Склонировать пространство…» и «Создать…».
- **Агенты.** По инструменту (Claude Code, Codex, Cursor — найденные): MCP «зарегистрирован /
  нет» с кнопкой, блок инструкций «записан · дата / устарел (есть новая версия) / нет» с
  кнопкой «Записать» или «Обновить». Ниже — «В проектах»: список клонов, где блок записан в
  `CLAUDE.md`/`AGENTS.md`, и кнопка «Записать в проект…» (выбор проекта из каталога).
  Подпись: «Секреты в инструкции не попадают — только имена переменных».
- **Окружение.** Python-окружение практик (`~/.practices/runtime`): версия, дата установки,
  «Переустановить»; CLI: путь `~/.practices/bin/practicesctl`, версия; «Открыть ~/.practices
  в Finder».

Состояния, которые нужно нарисовать: всё настроено; remote не задан; блок инструкций устарел;
инструмент не найден на машине; ошибка push (нет прав) — полоса ошибки по шаблону States.

## Что не рисовать

Выбор папки — системный диалог. Ввод секретов — уже есть лист подключения. Тема одна, тёмная.
