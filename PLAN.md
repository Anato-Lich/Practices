# Practices — план и очередь задач

Обновлено: 25 сентября 2026. Этап 1 (монитор) сделан. Этап 2 (источники и секреты) — ядро, CLI и окно готовы. Этап 3 (практики) — запуск, связки, окно, поиск готовы. Этап 4 (MCP) — сервер, предложения, копии готовы.

Исходное описание идеи — артефакт «Sandbox — архитектура» (9 сентября). Этот файл его
заменяет: всё, что там решено и не пересмотрено, перенесено сюда, пересмотренное — в
`DECISIONS.md`.

## Что это

Персональное нативное приложение для macOS (строка меню + окно), инструмент времени
разработки. Две половины:

1. **Песочница источников данных.** Источник (Postgres X-Keeper, ClickHouse, Kafka, System
   API…) — объект первого класса: креды, документация, заметки и **практики** — именованные
   ячейки кода («Получение данных устройства») с кнопкой «Выполнить» и человекочитаемым
   результатом (таблица, JSON-дерево, текст), временем прогона и историей версий. Практику
   копируют в проект и знают, как она себя поведёт; изменения, сделанные в проекте, агент
   возвращает сюда через MCP.
2. **Монитор контейнеров и портов** поверх OrbStack (или любого Docker): кто занимает порт,
   какой контейнер тихо упал, остановить то, что не останавливается из терминала.

Не Postman: конструктора запросов и форм нет, работаем кодом.

## Устройство

```
Practices/
  PracticesCore/          Swift-пакет: ядро без UI + CLI practicesctl (как BatteryCore у Tandem)
    Sources/PracticesCore/
      Monitor/            lsof, docker ps, docker events, склейка по порту
      Sources/            (этап 2) реестр источников, секреты, предусловия, healthcheck
      Practices/          (этап 3) практики, прогоны, версии
      MCP/                (этап 4) MCP-сервер поверх ядра
  PracticesApp/           SwiftUI-приложение, xcodegen (project.yml)
  runtime/                (этап 3) Python-раннер практик, запускается через uv
  docs/design/            макеты
```

Данные пользователя — `~/.practices/`:

```
~/.practices/
  secrets.json            значения кредов, 0600, без шифрования (DECISIONS 3), не в git
  runs.sqlite             история прогонов практик и healthcheck
  registry/               локальный git без remote, секретов нет
    sources/
      xkeeper-pg/
        source.yaml       kind, описание, имена ключей, предусловия, теги
        notes.md          грабли, какие поля нужны чаще всего
        docs/             официальная документация, собранные заметки
        practices/
          device-info.py
          device-info.md  (необязательно) описание, параметры по умолчанию
```

## Этапы

Между этапами — пожить на результате. После каждого этапа следующий может понадобиться
в другом виде; тогда правим план, а не подгоняем жизнь под него.

### 0. OrbStack — сделано 25 сентября
Переезд с Docker Desktop: 22 работавших контейнера остановлены штатно, дампы Postgres и
счётчики ClickHouse сняты заранее (`~/Backups/docker-migration-2026-09-25/`). Встроенный
`orb docker migrate` не справился с containerd-хранилищем Docker Desktop 29 (тома созданы
пустыми, образы не перенесены), поэтому тома скопированы `tar`-ом и сверены по md5 всех

`docker compose up` из своих папок; внешние сети `sphere-net`, `monitoring`, `web` созданы
с прежними подсетями. Docker Desktop удалён деинсталлятором, `docker` указывает на OrbStack.
Compose-файлы менять не пришлось.

## Решения, которые не пересматриваем

- Инструмент времени разработки. Код проекта читает `os.environ` и не знает о Practices;
  удаление Practices с машины не ломает ни один проект при вручную выставленных переменных.
- Центральная сущность — источник, не проект. Общий ключ существует в одном месте.
- Не участвуем в проде и CI. Не генерируем compose-файлы, не оборачиваем `docker compose`.
- Конфликты портов показываем, но сами ничего не перекладываем.
- Только локально: никакой сети наружу, кроме запросов самих практик.
- Только macOS.
