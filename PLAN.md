Обновлено: 7 ноября 2026. Шаг 1 сделан (ядро, CLI, MCP, окно в прежнем виде на новом ядре;

## Что это

Одно место, где описаны все проекты пользователя: что куда входит, какие сервисы как связаны,
где креды, документация и готовый код запросов. Вместо походов по GitLab, GitHub и локальным
файлам. Искать в нём в первую очередь будет агент через MCP; окно — для обзора, правки и
объяснения другим разработчикам.

Нативное приложение для macOS (окно) + CLI `practicesctl` + MCP-сервер. Инструмент времени
разработки, только локально.

## Модель

```
пространство          X-Keeper, SphereTele — граница организации и доступа
  проект              device-analysis — набор репозиториев с общей целью; проект может
                      лежать внутри другого: x-factory → scada, erp, mes
    репозиторий       опознаётся по адресу remote, не по папке
    сервис            compose-сервис или внешняя система без репозитория
      точка входа     адрес, по которому к сервису ходят (у Postgres X-Keeper их четыре)
      практика        код запроса к этому сервису — принадлежит тому, к кому обращается
      связь           «я хожу в тот сервис, вот так и вот зачем» — хранится у вызывающего
  условие             «нужна корпоративная сеть» — заводится один раз, сервисы ссылаются
```

- Принадлежность задаёт пользователь. Раскладка папок на диске ни о чём не говорит.
- Репозиторий входит в один проект, проект — в одно пространство. Общее использование — связи.
- Проекты вкладываются: у проекта может быть родитель (`x-factory` объединяет `scada`, `erp`,
  `mes` — полноценные проекты со своими репозиториями). Глубина не ограничена.
- «Источника» как отдельной сущности нет: Kafka, Postgres X-Keeper, MoySklad — сервисы.
- У сервиса один идентификатор, уникальный по всем пространствам, и список других имён, под
  которыми его знают проекты. Один сервис — одна запись: ради этого проект и существует.

## Где что лежит

Знание разделено по виду (DECISIONS 6).

**Данные** — репозиторий пространства, git, по умолчанию `~/.practices/spaces/<пространство>/`:

```
x-keeper/
  space.yaml                      имя; где искать репозитории (GitHub-организации, группы GitLab)
  conditions.yaml                 именованные условия
  projects/
    device-analysis/
      project.yaml                имя, описание, репозитории с ролями
      chains/<имя>.py             связки практик
      services/
        device-analysis-api/
          service.yaml            карточка
          links.yaml              исходящие связи
          notes.md                грабли
          fields.yaml             словарь полей результатов
          docs.yaml               ссылки на документы (репозиторий + путь или url)
          practices/<имя>.py
```

**Тексты** о проекте (архитектура, как развернуть, решения) — в его репозитории
`<проект>-docs`, обычном репозитории проекта с ролью `docs`. Документация, которая уже лежит в
репозиториях кода, не копируется: на неё ссылается `docs.yaml`.

**Машинное** — `~/.practices/`, не в git:

```
secrets.json      значения ключей: сервис → окружение → ключ; 0600, без шифрования
runs.sqlite       история прогонов практик (без данных)
checks.json       последние результаты проверок
local.yaml        необязательно: пути репозиториев пространств, корни поиска клонов,
                  папки кода без git
```

Локальная копия репозитория находится сама: в корнях поиска (по умолчанию `~/Projects`)
читается `remote.origin.url` каждого `.git`. Это поиск места, а не структуры.

### Форматы

Идентификатор репозитория — адрес remote без протокола и `.git`, в нижнем регистре:
`gitlab.rnd.x-keeper.net/x-keeper-rnd/x-vision/x-vision-cloud`. `git@host:a/b.git` и
`https://host/a/b` дают одно и то же.

```yaml
# space.yaml
name: X-Keeper
hosting:
  - {host: github.com, owner: X-Keeper}
  - {host: gitlab.rnd.x-keeper.net, owner: x-keeper-rnd}
ignore:                               # не показывать в «Не распределено»
  - gitlab.rnd.x-keeper.net/x-keeper-rnd/kanban

# conditions.yaml
- id: corp-network
  name: Корпоративная сеть X-Keeper
  hint: Включите WireGuard-туннель
  reachable: ${XK_PG_HOST}:${XK_PG_PORT_DEVICES}   # необязательно; шаблон над ключами сервиса

# project.yaml  (папки проектов лежат плоско: projects/<id>/, вложенность — полем parent)
name: Device analysis
parent: x-factory                     # необязательно: проект-родитель
description: Анализ траекторий устройств
repos:
  - {repo: github.com/x-keeper/device_analysis, role: frontend}
  - {repo: github.com/x-keeper/device_analysis-api, role: backend}
folders:                              # код без git; путь — в local.yaml
  - {name: export_engine}

# service.yaml
id: xkeeper-pg
name: X-Keeper Postgres
kind: postgres
description: Базы X-Keeper, одна учётная запись на чтение. Никогда не писать.
tags: [read-only, prod-data]
repo: github.com/x-keeper/...        # нет строки — внешний сервис
aliases: [pg.x-keeper.net]           # другие имена: compose-сервис, хост
envs: [prod]
keys: [XK_PG_HOST, XK_PG_USER, XK_PG_PASSWORD, XK_PG_PORT_DEVICES]
endpoints:
  - id: devices
    address: ${XK_PG_HOST}:${XK_PG_PORT_DEVICES}
    requires: [corp-network]
requires: []                          # условия для сервиса целиком
guards:
  - 'Каждое соединение: default_transaction_read_only = on'

# links.yaml (у вызывающего сервиса)
- to: xkeeper-pg
  endpoint: devices
  env: prod
  via: db                             # http | topic | db | network | build
  what: x-keeper_devices.devices      # топик, таблица, путь
  access: read                        # read | write
  why: Модель и дата создания устройства для расчёта
  practice: xkeeper-pg/device-info
  names: {SRC_DEVICES_HOST: XK_PG_HOST}   # переменная вызывающего → ключ сервиса
  file: ops/.env                      # env-файл в репозитории вызывающего
  origin: manual                      # derived:<файл> — вывел сканер; code:<файл> — прочитал в коде агент
```

Ссылки `сервис/практика` и `chains/имя`, метка `# practices: <ссылка>@v<N>` в скопированном
коде и версия как номер коммита файла — без изменений.
