Обновлено: 25 сентября 2026. Этап 1 (монитор) сделан, пользователь живёт на нём; дальше этап 2.

## Что это

Персональное нативное приложение для macOS (строка меню + окно), инструмент времени
разработки. Две половины:

1. **Песочница источников данных.** Источник (Postgres X-Keeper, ClickHouse, Kafka, System
   API…) — объект первого класса: креды, документация, заметки и **практики** — именованные
   ячейки кода («Получение данных устройства») с кнопкой «Выполнить» и человекочитаемым
   результатом (таблица, JSON-дерево, текст), временем прогона и историей версий. Практику
   копируют в проект и знают, как она себя поведёт; изменения, сделанные в проекте, агент
   возвращает сюда через MCP.
2. **Монитор контейнеров и портов** поверх OrbStack (или любого Docker): кто занимает порт,
   какой контейнер тихо упал, остановить то, что не останавливается из терминала.

Не Postman: конструктора запросов и форм нет, работаем кодом.

## Устройство

```
Practices/
  PracticesCore/          Swift-пакет: ядро без UI + CLI practicesctl (как BatteryCore у Tandem)
    Sources/PracticesCore/
      Monitor/            lsof, docker ps, docker events, склейка по порту
      Sources/            (этап 2) реестр источников, секреты, предусловия, healthcheck
      Practices/          (этап 3) практики, прогоны, версии
      MCP/                (этап 4) MCP-сервер поверх ядра
  PracticesApp/           SwiftUI-приложение, xcodegen (project.yml)
  runtime/                (этап 3) Python-раннер практик, запускается через uv
  docs/design/            макеты
```

Данные пользователя — `~/.practices/`:

```
~/.practices/
  secrets.json            значения кредов, 0600, без шифрования (DECISIONS 3), не в git
  runs.sqlite             история прогонов практик и healthcheck
  registry/               локальный git без remote, секретов нет
    sources/
      xkeeper-pg/
        source.yaml       kind, описание, имена ключей, предусловия, теги
        notes.md          грабли, какие поля нужны чаще всего
        docs/             официальная документация, собранные заметки
        practices/
          device-info.py
          device-info.md  (необязательно) описание, параметры по умолчанию
```

## Этапы

Между этапами — пожить на результате. После каждого этапа следующий может понадобиться
в другом виде; тогда правим план, а не подгоняем жизнь под него.

### 0. OrbStack — сделано 25 сентября
Переезд с Docker Desktop: 22 работавших контейнера остановлены штатно, дампы Postgres и
счётчики ClickHouse сняты заранее (`~/Backups/docker-migration-2026-09-25/`). Встроенный
`orb docker migrate` не справился с containerd-хранилищем Docker Desktop 29 (тома созданы
пустыми, образы не перенесены), поэтому тома скопированы `tar`-ом и сверены по md5 всех
файлов (19 из 19 совпали), образы перенесены `docker save | docker load`, проекты подняты
`docker compose up` из своих папок; внешние сети `sphere-net`, `monitoring`, `web` созданы
с прежними подсетями. Docker Desktop удалён деинсталлятором, `docker` указывает на OrbStack.
Compose-файлы менять не пришлось.

### 1. Монитор — сделано
- [x] Ядро: слушающие порты (`lsof`), контейнеры (`docker ps -a`), склейка по порту,
  проект — по лейблам compose или по cwd процесса.
- [x] Поток `docker events`: упал с ненулевым кодом, OOM, unhealthy, перезапуски по кругу →
  уведомление.
- [x] `practicesctl ports | containers | conflicts [--all] | watch | logs`.
- [x] Приложение в строке меню: значок с числом упавших, поповер «Внимание / Конфликты портов
  / Порты / Контейнеры», stop / kill / логи / браузер / адрес `*.orb.local`.
- [x] Конфликты до `docker compose up`: порты из compose-файлов `~/Projects`, занятые чужим
  процессом или контейнером, с подсказкой адреса OrbStack без публикации порта; AirPlay
  Receiver на 5000/7000 распознаётся отдельно. `--all` показывает проекты, которые
  столкнутся между собой, и устаревшие overlay-файлы.
- [x] Автозапуск при входе (галочка в поповере), `install.sh` ставит в /Applications.

Живой пример конфликта, оставленный нарочно: фронтенд imu-sphere хочет 5173, его держит `node`
из SphereTele; сейчас фронтенд запущен на 5175 через `~/Backups/docker-migration-2026-09-25/imu-ports.yml`,
а в OrbStack доступен как `imu-sphere-frontend.imu-sphere.orb.local:5173` — Vite отвечает 403,
пока `.orb.local` не добавлен в `server.allowedHosts` (первый кандидат в практики).

Найдено попутно: `docker-compose.ports.yml` в imu-sphere, device_analysis и device_analysis-api
ссылаются на сервисы, которых нет ни в одном основном файле папки, — устарели.

Проверка гипотезы: через неделю видно, смотрит ли пользователь в строку меню и ловит ли
уведомления о падениях. Если нет — пересматриваем остальное, пока не вложились.

### 2. Источники и секреты
- Реестр `~/.practices/registry` (git), `source.yaml`, заметки, документация.
- Секреты в `secrets.json`; UI показывает «задано / не задано» и даёт вписать значение.
- Предусловия (`vpn`, `reachable host:port`) проверяются до запуска: «нужен VPN» вместо
  таймаута через 30 секунд.
- Healthcheck по кнопке «проверить всё».
- `practicesctl run <source…> -- <команда>` — креды в окружение дочернего процесса, файл на
  диск не пишется.
- Импорт: шесть источников Connectors и его `.env` — первые записи реестра.
- Doctor: `.env` в `~/Projects` с ключами, которых нет в реестре; одинаковые значения в
  разных `.env` (кандидаты в общий источник).

### 3. Практики
- Ячейка кода: Python, договорённость — функция `run(...)` с параметрами по умолчанию,
  креды читаются из `os.environ` по имени. Для SQL-источников допустима ячейка чистым SQL.
- Раннер: `uv run` в общем окружении `~/.practices/runtime` (psycopg, clickhouse-connect,
  kafka, httpx, pandas…), креды источника в env, результат — JSON с формой:
  список записей / DataFrame → таблица, dict → дерево, остальное → текст; stdout отдельно.
- Прогон: время, строки, размер; история в `runs.sqlite` рядом с версией кода — «v3 4.2 с,
  v4 1.8 с».
- Версии — коммиты реестра. Список ревизий, дифф, откат.
- Копирование в проект вставляет метку `# practices: <source>/<practice>@v<N>`.

### 4. MCP и синхронизация с проектами
- `practicesctl mcp` (stdio), инструменты: `list_sources`, `get_source`, `get_practice`,
  `search`, `run_practice`, `propose_update(practice, code, note)`, `add_note`.
- `propose_update` кладёт предложение на ревью; приложение показывает дифф, пользователь
  принимает — новая версия.
- Doctor по меткам в `~/Projects`: копии со старой версией; копии, изменённые в проекте и
  не отправленные обратно.
- Значения секретов агенту не отдаются (DECISIONS 4). Для источников с тегом `pii`
  `run_practice` через MCP выключен или возвращает только форму результата.

## Решения, которые не пересматриваем

- Инструмент времени разработки. Код проекта читает `os.environ` и не знает о Practices;
  удаление Practices с машины не ломает ни один проект при вручную выставленных переменных.
- Центральная сущность — источник, не проект. Общий ключ существует в одном месте.
- Не участвуем в проде и CI. Не генерируем compose-файлы, не оборачиваем `docker compose`.
- Конфликты портов показываем, но сами ничего не перекладываем.
- Только локально: никакой сети наружу, кроме запросов самих практик.
- Только macOS.
